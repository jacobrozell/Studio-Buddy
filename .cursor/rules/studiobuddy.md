# Studio Buddy — agent rules

Recurring conventions so agents don't reintroduce fixed mistakes.

## Project
- The `.xcodeproj` is generated by XcodeGen and **gitignored** — never commit it.
  After editing `project.yml`, run `xcodegen generate`.
- Git remote must use the `github.com-personal` SSH host (`jacobrozell` key), not bare
  `github.com` (that routes to the work account). The GitHub repo is
  `Studio-Buddy`. Example remote:
  `git@github.com-personal:jacobrozell/Studio-Buddy.git`
- Build/test with XcodeBuildMCP (see `.cursor/mcp.json`) or:
  `xcodebuild test -scheme StudioBuddyCI -destination 'platform=iOS Simulator,name=iPhone 17'`.
- Full local gate: `Scripts/ci/verify-local.sh` (SwiftLint + unit + all UI schemes).
- UI schemes: `StudioBuddyUISmoke`, `StudioBuddyUILandscape`, `StudioBuddyUIAccessibility`, `StudioBuddyUIPad`.

## Architecture
- Services (`SequencingEngine`, `AudioAnalyzer`, `WaveformGenerator`) must not
  import SwiftUI/UIKit — keep them pure and unit-tested. See `specs/Architecture.md`.
- One source of truth: URLs → `AppLinks`, surface gating → `ReleaseSurface`,
  UI-test ids → `A11yID`.

## Accessibility (release gate)
- Icon-only controls need an `accessibilityLabel`; decorative images use
  `.accessibilityHidden(true)`; respect Reduce Motion. See `specs/Accessibility.md`.
- `Tab { … }` content is `TabContent`, not a `View` — apply view modifiers to
  the view *inside* the tab closure, not to `Tab` itself.

## Layout
- Split navigation and sidebar tabs only when **both** size classes are regular
  (iPad, iPhone Duo inner display, a tall resizable window). Do not use
  `userInterfaceIdiom` for chrome. iPhone landscape stays a phone stack.

## Migrations
- Adding stored properties to `@Model`s relies on lightweight migration during
  pre-release dev; introduce a versioned schema before shipping data the user
  can't lose.
